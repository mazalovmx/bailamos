# Исправления по аудиту трёх пользовательских сценариев

Дата проверки: 4 октября 2026. Основание: [исходный аудит](audit-three-personas.md) и последующее поручение исправить выявленные проблемы. Базовая ревизия: `34e781a93b885242004a28c1bc50b77ef431ff82`; проверена рабочая копия с изменениями, без создания коммита. Платежи и продажа билетов не добавлялись.

## Результат для пользователей

**Школа.** Владелец с личным профилем создаёт отдельную школу через «Мои школы», назначает администратора и переходит к единому редактору с уже выбранной школой. Регулярное расписание можно изменять и продолжать без удаления записей участников. Отменённые и индивидуально перенесённые занятия сохраняются. Назначенный администратор видит участников и получает уведомление о новой записи; отзыв доступа применяется при следующем запросе.

**Приезжий преподаватель.** Разовый мастер-класс по-прежнему создаётся без школы. Регистрация с подтверждением email возвращает к созданию события. Изменение времени или места формирует сообщение участникам с актуальными условиями; ручной адрес сохраняется при передаче в календарь.

**Посетитель.** Регистрация возвращает к исходному событию. Город, стиль и уровень сохраняются при переходах между основными представлениями поиска. Повторяющаяся серия занимает одну карточку в списке. Событие можно приватно сохранить отдельно от отметки участия. Блок участия расположен перед картой и описанием; предложение установки приложения больше не перекрывает карточку.

Браузерные проходы выполнены через реальные формы и письмо Mailpit: отдельные аккаунты и контексты, EN, desktop 1280×900 и mobile 390×900; ключевые формы и переходы дополнительно RU/ES. После регистрации не было ручного выставления `emailVerified` или обхода потерянного перехода. Назначение/отзыв администратора и доступ к участникам дополнительно проверены HTTP-запросами.

## Техническая оценка

**Надёжность.** Главный риск потери RSVP при изменении серии устранён тестируемой синхронизацией без удаления дат. Проверены блокировки записи, конфликт версий, повтор создания с ключом, права менеджеров, приватность закладок и черновиков. Outbox устраняет разрыв между сохранением изменения и постановкой сообщения на доставку. Все эти гарантии относятся к указанным командам, а не автоматически ко всем операциям приложения.

**Clean Code.** Удалены доказанно неиспользуемые альтернативные формы, уточнено название количества повторов, добавлены тесты наблюдаемого поведения вместо проверки внутренней структуры реализации. Остались крупные страницы и инфраструктурные модули; это не завершённая переработка всей кодовой базы. Старое входное имя `recurrenceWeeks` принимается для совместимости, новый UI использует `recurrenceCount`.

**Clean Architecture.** Правила статуса, блокировки и постановки уведомлений теперь общие для нескольких входов; они не импортируют Next.js. Это практическое улучшение единообразия и тестируемости. Общий пакет по-прежнему зависит от Prisma, а часть прикладных функций знает HTTP-ошибки. Полностью независимый от инфраструктуры доменный слой не заявляется. Следующий безопасный этап — выделение интерфейсов хранилища/доставки за существующими контрактами, затем дробление редактора; переписывание всех слоёв одновременно не требуется.

Регрессионный порядок дальнейшего рефакторинга: сначала сохранить тесты идентичности дат и аудитории уведомления, затем извлечь чистые вычисления расписания и diff, после этого заменить прямые зависимости адаптерами. Контрактные проверки web/admin/import должны оставаться общими; форматирование не заменяет проверку бизнес-правил.

## Миграции и эксплуатация

Применены `202610030001_event_safety` и `202610030002_school_ownership` в изолированной и локальной БД. Перед изменением локальной БД создан и проверен каталог резервной копии PostgreSQL custom-format. Файл `test-results/persona-audit/local-before-fixes.dump` приватный и не включается в публикуемые материалы.

Первая миграция добавляет версию события, ключ создания, подтверждение места, идентичность слота расписания, outbox и закладки. Ограничение уникальности времени даты отложено до конца транзакции: это позволяет безопасно сдвинуть серию в прежние слоты без временного удаления строк. Вторая добавляет явное право управления администраторами школы. Существующие владельцы-школы поддерживаются; создание новой отдельной школы не заменяет личный профиль.

Для повторной доставки должен постоянно работать worker с задачей `events.notifications` (интервал 10 секунд). Локально запущена только эта задача в отдельной очереди `dance-event-delivery-local`, SMTP направлен в локальный Mailpit. После перезапуска среды её нужно запустить снова либо настроить штатный постоянный worker:

```powershell
$env:WORKER_JOBS='events.notifications'
$env:WORKER_QUEUE='dance-event-delivery-local'
pnpm.cmd worker
```

Не направлять worker с ограниченным набором задач в очередь с другими заданиями. Для полного штатного worker переменные ограничения не устанавливаются. Ошибки доставки видны в структурированных логах (`event_delivery_failed`, `event_outbox_unavailable`) и полях `EventDelivery.attempts/retryAt/lastError/completedAt`. Отдельная панель метрик доставки не добавлялась. На внешнее окружение изменения не развёртывались.

## Ограничения и следующая проверка

- Доставка внешних сообщений — **at least once**. Сбой после принятия письма SMTP, но до фиксации транзакции может дать повтор; стабильный Message-ID помогает трассировке, но не гарантирует дедупликацию получателем. Google OAuth, Telegram, push и реальный импорт в Google/Apple Calendar не проверялись внешними аккаунтами. Проверены форматы/URL и локальная почта.
- Продление ограничено 52 новыми датами за запрос и 520 материализованными датами серии. Очень старая серия может достигнуть горизонта генерации; бесконечное продолжение не заявляется.
- Идемпотентность создания действует при переданном `operationId`; новый UI его передаёт, прежние API-клиенты без ключа остаются совместимыми. Защита версии обязательна для полного редактирования. Это не утверждение о сериализации всех возможных действий, включая одновременные RSVP и отмену.
- Старые ссылки только с `?date=` неоднозначны, если после сдвига всей серии прежнее время одной даты становится текущим временем другой. RSVP и ICS UID сохраняются, но для таких исторических URL нельзя однозначно восстановить намерение без ID даты. Текущий выбор отдаёт приоритет точному актуальному времени; следующая совместимая эволюция ссылок — явный occurrence ID.
- Представления имеют разные естественные окна: карта — ближайшие дни/видимая область, календарь — месяц, занятия — неделя. Сохранение фильтров не означает одинакового числа карточек. Подсказка будущей недели в расписании требует отдельного углубления для сочетания фильтров дня недели/части дня; этот крайний случай не считается закрытым браузерной проверкой.
- Outbox внедрён для описанных изменений событий, школьной админки и импорта. Старые напоминания и отдельные модерационные операции не получили автоматически тех же гарантий. Общие замечания архитектурного обзора не равны исправленным дефектам F01–F16; полная изоляция домена и унификация всех служебных путей остаются отдельной работой.

Приоритет следующего расширения: стабильные ссылки на ID даты и оставшиеся сочетания фильтров → распространение контрактов доставки на модерацию/напоминания → независимые интерфейсы домена и наблюдаемость. Эти ограничения приведены явно, чтобы результат не читался как обещание полной формальной проверки всех сценариев приложения.
